# XingyuBot 伺服器管理後台：反應身分組、私人頻道、伺服器設定、警告與抽獎

## 背景與動機

[伺服器管理後台第一版](server-dashboard-spec.md)只處理自動通知，[第二案](server-dashboard-dynamic-voice-spec.md)加入動態語音。其餘伺服器功能原本排定依序加入：反應身分組、私人頻道、伺服器設定與警告。這一案把它們一次補齊，另外加入抽獎的檢視與管理。

五項功能現在都只能在 Discord 上操作，各有各的問題：

1. **反應身分組**（訊息下方的按鈕，按一下取得或移除身分組）：管理員看不到伺服器裡有哪些反應身分組訊息；指令只能在訊息所在的頻道操作，要先複製訊息 ID；訊息內容只能是純文字；按鈕順序無法調整；身分組被刪除後，按鈕留著，按下去才報錯。bot 重啟時，頻道已不存在的紀錄會被靜默刪除。
2. **私人頻道**：`/ticket setup` 是測試版，只能指定分類。頻道名稱是 `ticket-<使用者名稱>`，沒有管理身分組、沒有開單數量限制，關閉只是鎖住發言，之後沒有任何方式重開或清理。
3. **伺服器設定**：只有「語音時數統計」與「警告 N 次後自動禁言」兩項。前者沒有任何指令能開關，只能直接改資料庫；後者有欄位卻沒有實作。
4. **警告**：只能用指令一筆一筆查，看不到這個伺服器發過哪些紀錄。
5. **抽獎**：任何人都能用 `/giveaway create` 發起抽獎，但管理員看不到伺服器裡有哪些抽獎、誰參加、誰中獎；只有發起人能提前結束或重抽，發起人不在時沒人能處理。

## 目標與非目標

**目標**
- 有權限的管理員能在網頁上完整管理反應身分組、私人頻道、伺服器設定與警告紀錄，效果與指令一致且立即生效。
- 反應身分組的訊息能用文字與 embed 編排，並在存檔前看到 Discord 上的樣子。
- 私人頻道能設定多個開單大廳，各自有管理身分組、命名規則與開單限制。
- 「警告 N 次後自動禁言」真正運作，語音時數統計可以開關並看排行榜。
- 管理員能在後台查詢紀錄、新增警告，也能執行禁言、踢出與停權。
- 管理員能看到伺服器的所有抽獎、參加者與中獎者，並能代替發起人提前結束與重抽。
- 只負責其中一部分工作的管理人員，例如只有懲處權限的人，也能進後台使用他有權限的區塊。
- 寬度 360px 以上的手機可以完整操作。

**非目標**
- 反應身分組的行為模式：單選（互斥）、只能拿不能退、下拉選單。
- 私人頻道的開單表單、對話紀錄（transcript）保存、關閉後自動刪除。
- 懲處時的身分組位階檢查，維持與指令一致只看權限。
- 從後台發起抽獎、修改抽獎內容、調整參加者權重。
- 個人後台，包括個人的抽獎紀錄；異動歷史、英文介面。

## 已定案的前提

- 沿用前兩案的地基：Discord 登入與 session、伺服器清單、存取檢查、bot 不在伺服器或使用者沒有權限時的處理、同時編輯的衝突比對與表單暫存、伺服器端重新檢查所有限制、360px 可操作。本文只寫不同或新增的部分。
- 後台 API 放在 XingyuBot 的 web 服務，前端放在 domalyze_frontend 的 `main` 分支，與前兩案相同。
- 五項功能寫在同一份規格，任務卡再依功能拆開。

## 範圍

- 伺服器頁的側欄新增五個區塊：反應身分組、私人頻道、警告、抽獎、基本設定。
- 伺服器頁的進入條件放寬為「有任一區塊的權限」，各區塊依自己的權限顯示。
- 反應身分組：訊息一覽、新增、編輯內容與按鈕、排序、預覽、刪除、失效處理、重新發送。
- 私人頻道：多個大廳的設定、大廳訊息編輯、私人頻道清單、鎖定、重開與刪除。
- 基本設定：語音時數統計開關與排行榜、自動禁言設定。
- 警告：本伺服器的紀錄清單與篩選、查詢成員的跨群紀錄、新增警告、移除紀錄、執行禁言、踢出與停權。
- 抽獎：抽獎清單、單一抽獎的參加者與中獎者、提前結束、重抽。
- 指令配合修改：反應身分組的重啟清理、`/ticket setup` 支援新設定、`/timeout`、`/kick`、`/ban` 一律寫紀錄、`/warning add` 觸發自動禁言、新增基本設定的指令。

## 詳細規格

### 頁面與導覽

- 側欄順序：通知、動態語音、反應身分組、私人頻道、警告、抽獎、基本設定。頁面標題維持「伺服器設定」，所以設定區塊命名為「基本設定」，避免與標題重複。
- 每個區塊有自己的網址，與第二案相同。
- 使用者只看得到自己有權限的區塊。進入伺服器頁時，停在順序上第一個有權限的區塊；有 Manage Channels 的人仍然預設停在通知，與現有行為相同。
- 直接打開沒有權限的區塊網址時，提示沒有權限，並導到第一個有權限的區塊。

### 權限

權限看的是使用者在伺服器層級的權限，Administrator 與伺服器擁有者視同具備所有權限，與第一版相同。

| 區塊／動作 | 需要的權限 |
|---|---|
| 通知、動態語音 | Manage Channels（不變） |
| 反應身分組 | Manage Roles |
| 私人頻道 | Manage Channels |
| 基本設定 | Manage Server |
| 警告：查看紀錄、查詢跨群紀錄 | 能進入伺服器頁即可，與指令的查詢不需權限一致 |
| 警告：新增警告 | Manage Messages |
| 警告：移除紀錄 | Kick Members、Ban Members、Manage Messages 其中一個 |
| 禁言 | Moderate Members |
| 踢出 | Kick Members |
| 停權 | Ban Members |
| 抽獎：查看、提前結束、重抽 | Manage Messages |

- **進入條件**：bot 在伺服器裡，而且使用者至少有上表其中一項權限：Manage Channels、Manage Roles、Manage Server、Manage Messages、Kick Members、Ban Members、Moderate Members。
- 伺服器清單的「已邀請」組改用這個進入條件。第一版「邀請完成後有 Manage Channels 才進入通知頁」的規則，改成「符合進入條件就進入伺服器頁，停在第一個有權限的區塊；不符合就回到清單，並提示需要哪些權限」。
- 沒有 Manage Channels 的人看不到通知與動態語音區塊。
- 從後台執行的動作由 bot 代為執行，Discord 稽核紀錄的執行者會是 bot。後台執行時，原因前面加上「<管理員的 Discord username> 透過後台：」，讓稽核紀錄追得到是誰做的。自動禁言由 bot 自己觸發，原因不加這個前綴。

### 訊息編輯器

反應身分組訊息與私人頻道的大廳訊息共用同一套訊息編輯器。

- 訊息由兩部分組成：文字與 embed，兩者都是選填，但至少要填一個。
- embed 欄位：標題、標題連結、說明、顏色、作者（名稱、連結、圖示網址）、field（名稱、內容、是否並排，可新增、刪除、調整順序）、圖片網址、縮圖網址、footer（文字、圖示網址）。
- 各欄位的長度與數量上限照 Discord 的規定；超過時不能存，並指出是哪個欄位。
- 編輯時即時預覽，顯示接近 Discord 的外觀，包括訊息下方的按鈕。預覽只是近似，以 Discord 實際顯示為準。

### 反應身分組

**一覽**
- 列出這個伺服器所有反應身分組訊息，每筆顯示所在頻道、訊息內容的摘要、按鈕清單（標題、emoji、對應的身分組），並提供跳到 Discord 原訊息的連結。
- 依頻道在伺服器中的位置排序，同一頻道內依訊息時間排序。
- 沒有任何反應身分組時，顯示說明：功能怎麼運作，以及 bot 的身分組位階要高於要發放的身分組。

**新增**
- 先選擇要掛在哪則訊息上：
  - **發新訊息**：選頻道，用訊息編輯器編排內容，bot 發出新訊息。
  - **掛到 bot 既有的訊息**：從選定頻道最近 100 則訊息中 bot 發的挑選，最多列 25 則；或直接貼上 Discord 的訊息連結。帶有其他互動元件的訊息不列出；已經是反應身分組的訊息會列出，點選後直接進入它的編輯畫面。這兩類都不算在 25 則內。貼上的連結必須屬於這個伺服器，而且訊息是 bot 發的，否則說明原因並擋下。
- 既有訊息已經帶有其他按鈕或互動元件，例如投票，就不能掛反應身分組，並說明原因。已經是反應身分組的訊息，則直接進入它的編輯畫面。
- 既有訊息掛上反應身分組後，一律視為反應身分組訊息，內容也能在後台修改，與 `/reactrole editmessage` 一致。編輯器先帶入訊息目前的文字與 embed。訊息有兩則以上的 embed 或帶有附件時，只能管理按鈕，不能改內容，並說明原因；embed 裡編輯器沒有的欄位，例如時間戳，編輯時原樣保留。
- 至少要有一顆按鈕才能存檔。

**按鈕**
- 每顆按鈕設定身分組、標題、emoji（選填）與樣式。emoji 可以是 Unicode emoji 或這個伺服器的自訂 emoji，從選單挑選；用指令設定、已經無效的 emoji，例如自訂 emoji 被刪除，標示失效。樣式有 Discord 的四種：主要、次要、成功、危險。
- 同一則訊息裡，同一個身分組只能出現一次。
- 一則訊息最多 25 顆按鈕。按鈕可以調整順序，每 5 顆自動換列，不能手動指定列。
- 身分組選單列出伺服器所有身分組。以下身分組顯示但停用，並說明原因，與指令一致：
  - @everyone 與由整合服務管理的身分組。
  - 位階不低於 bot 最高身分組的身分組。
  - 位階不低於操作者最高身分組的身分組；伺服器擁有者不受這條限制。
- 存檔時只對新增或有變動的按鈕檢查身分組的可選範圍。訊息裡留著失效按鈕，或有位階不低於操作者的既有按鈕，例如別人用指令設的，仍然可以存檔。位階不低於操作者的按鈕只能刪除，不能修改；失效按鈕可以修改或刪除。
- 身分組帶有危險權限時，例如 Administrator、Manage Server、Manage Roles、Ban Members，顯示警告「任何人按下按鈕都會取得這些權限」，但仍然可以設定，與指令一致。

**存檔**
- 存檔後立即更新 Discord 上的訊息內容與按鈕，不需要重啟 bot。
- 用指令新增的按鈕排在最後面。

**刪除整則反應身分組訊息**
- 確認視窗讓管理員選擇：刪除 Discord 上的訊息，或只拿掉按鈕、保留訊息。預設是刪除訊息。
- 兩種做法都會移除 bot 的紀錄。

**失效處理**
- 每次打開頁面時檢查，以下情況標示失效並說明原因，由管理員處理：
  - 訊息或所在頻道在 Discord 被刪除：可以「重新發送」，或移除紀錄。
  - 按鈕的身分組被刪除，或位階變得不低於 bot：該按鈕標示失效，可以修改或刪除。
- 重新發送時，管理員選擇頻道，預設是原頻道；原頻道已被刪除時必須重新選。發送的內容是最後一次記錄的訊息內容加上所有有效的按鈕；失效的按鈕略過，並告知略過了哪幾顆。有兩則以上 embed 或帶附件的訊息只記錄按鈕，重新發送時必須用編輯器重新編排內容。
- 為了能重新發送，bot 要記住每則反應身分組訊息的內容，包括掛在既有訊息上的。用指令改內容時一併更新。
- 上線前就存在的反應身分組紀錄，上線時讀取 Discord 上的訊息存下內容；讀不到的標示「沒有可重新發送的內容」，只能移除紀錄，或用編輯器重新編排後發送。
- bot 重啟時，不再自動刪除頻道已不存在的反應身分組紀錄，統一由後台處理。

**bot 權限警告**

照第二案的模式：顯示缺少的權限與後果，權限不足仍然可以存檔。

| bot 缺少的權限 | 檢查位置 | 後果 |
|---|---|---|
| Manage Roles | 伺服器層級 | 按下按鈕無法給予或移除身分組 |
| View Channel | 訊息所在頻道 | 無法發送或更新訊息 |
| Send Messages | 訊息所在頻道 | 無法發送新訊息或重新發送 |
| Embed Links | 訊息所在頻道 | embed 無法顯示 |
| Read Message History | 訊息所在頻道 | 無法讀取既有訊息 |

### 私人頻道

**大廳**
- 一個伺服器可以有多個開單大廳，各自設定。
- 每個大廳的設定：
  - **大廳頻道**：選擇既有的文字頻道，或讓 bot 新建一個。新建時要選它所在的分類與名稱。
  - **私人頻道所在的分類**：必填，可以和大廳頻道所在的分類不同。
  - **管理身分組**：可以設多個，也可以不設。管理身分組看得到這個大廳的所有私人頻道，也能鎖定、重開、刪除。修改管理身分組時，套用到這個大廳所有還沒刪除的私人頻道：新增的身分組立刻看得到，已鎖定的頻道要重開後才能發言；移除的身分組，頻道上的權限覆寫直接刪除。
  - **頻道名稱前綴**：預設 `ticket`。私人頻道的名稱是「前綴-流水號」，例如 `report-0012`。前綴照 Discord 頻道名稱的規則處理（例如轉小寫、空白換成 `-`），處理後必須是 1 到 20 個字元，否則不能存。不同大廳可以用相同的前綴。
  - **每人同時只能一張**：預設開啟。
  - **同時開啟上限**：選填，留空代表不限。
  - **大廳訊息**：用訊息編輯器編排，另外可以設定開單按鈕的文字與 emoji。預設沿用現在的內容：「私人頻道系統／點擊下方按鈕以建立私人頻道」，按鈕「建立私人頻道」。
- 同一個頻道只能當一個大廳。
- 存檔後立即更新 Discord 上的大廳訊息，不需要重啟 bot。

**開單**
- 流水號每個大廳各自遞增，四位數補零，超過 9999 時照常往上加。刪除的號碼不會回收。
- 「每人一張」與「同時開啟上限」都以大廳為單位，所有還沒被刪除的私人頻道都算在內，包括已鎖定的。
- 判斷限制時以按下按鈕當下的狀態為準：已經在 Discord 被手動刪除的私人頻道不算，並一併移除紀錄。多人同時按下時，也不能超過限制。
- 超過限制時，按下開單按鈕只有本人看得到提示：每人一張時告知他已經有的頻道，額滿時告知目前已額滿。
- 新的私人頻道複製所在分類的權限覆寫，再設成 @everyone 看不到；建立者、管理身分組與 bot 都能查看、發言與讀取訊息紀錄。沒設管理身分組時，就只有分類覆寫原本看得到的身分組、建立者與 bot 看得到，與現在的行為相同。

**鎖定、重開與刪除**
- **鎖定**：頻道裡除了 bot 以外，所有權限覆寫的對象都不能再發言，包括建立者、管理身分組與 @everyone；Administrator 與伺服器擁有者不受頻道覆寫限制，仍然可以發言。頻道保留。
- **重開**：恢復到鎖定前的發言權限。
- **刪除**：刪除 Discord 頻道，對話無法復原。刪除前要二次確認，確認視窗寫明「對話無法復原」。
- 誰能做什麼：

| 動作 | 建立者 | 管理身分組 | 有伺服器層級 Manage Channels 的人 |
|---|---|---|---|
| 鎖定 | 可以（Discord 內） | 可以（Discord 內） | 可以（Discord 內或後台） |
| 重開 | 不行 | 可以（Discord 內） | 可以（Discord 內或後台） |
| 刪除 | 不行 | 可以（Discord 內） | 可以（Discord 內或後台） |

- 在 Discord 內，私人頻道的置頂訊息提供鎖定按鈕；鎖定後換成重開與刪除按鈕。按下沒有權限的按鈕時，只有本人看得到提示。

**私人頻道清單**
- 依大廳分組，列出所有還沒刪除的私人頻道。每筆顯示頻道名稱、建立者、建立時間、狀態（開啟中或已鎖定），已鎖定的再加上鎖定者與鎖定時間。
- 進入頁面時載入，另有手動重新整理，不即時更新。
- 在 Discord 被手動刪除的私人頻道，載入時自動移除紀錄，不顯示，也不再占用名額。

**移除大廳**
- 移除大廳要二次確認。移除後不能再從這個大廳開新單：大廳訊息的開單按鈕拿掉，訊息與大廳頻道本身保留。
- 大廳底下還存在的私人頻道保留，在清單上改列到「未歸屬的私人頻道」。原本的管理身分組失去在 Discord 內鎖定、重開、刪除的權限，只剩有伺服器層級 Manage Channels 的人能處理。

**失效處理**
- 每次打開頁面時檢查。大廳頻道被刪除，或大廳訊息被刪除時，大廳標示失效。可以重新選頻道並重新發送大廳訊息，或移除大廳。
- 私人頻道所在的分類被刪除時，大廳標示失效，必須重新選分類才能再開單。

**bot 權限警告**

| bot 缺少的權限 | 檢查位置 | 後果 |
|---|---|---|
| Manage Channels | 私人頻道所在分類 | 無法建立或刪除私人頻道 |
| Manage Roles | 私人頻道所在分類 | 無法設定私人頻道的可見範圍，也無法鎖定、重開 |
| View Channel | 大廳頻道 | 無法發送或更新大廳訊息 |
| Send Messages | 大廳頻道 | 無法發送大廳訊息 |
| Embed Links | 大廳頻道 | 大廳訊息的 embed 無法顯示 |
| Manage Messages | 私人頻道所在分類 | 無法置頂私人頻道的操作訊息 |

**既有的測試版資料**
- 既有的大廳套用預設值：私人頻道所在的分類是大廳頻道所在的分類（現在的行為），沒有管理身分組、前綴 `ticket`、每人一張開啟、不設上限，大廳訊息沿用現在的內容。
- 既有的 `ticket-<名稱>` 頻道照常列出，不改名，也算在名額內。流水號從 1 開始。已鎖定的既有頻道沿用現有紀錄的鎖定者與鎖定時間；測試版沒有存鎖定前的權限，重開時建立者、管理身分組與 bot 恢復發言，其餘回到分類的權限覆寫。
- 上線時把既有頻道的置頂操作訊息換成新的鎖定、重開、刪除按鈕；置頂訊息已經不在的頻道，只能從後台操作。
- 既有頻道依所在分類，歸屬到使用該分類的大廳。對不到或對到多個大廳時，列在「未歸屬的私人頻道」，可以鎖定、重開、刪除，但不占任何大廳的名額；只有伺服器層級 Manage Channels 的人能操作。

### 基本設定

**語音時數統計**
- 開關這個伺服器的語音時數統計，存檔後立即生效。開啟時，bot 每分鐘替語音頻道中沒有靜音、也沒有拒聽的成員累計時數，AFK 頻道不算，與現在的行為相同。
- 關閉時保留已累計的資料，重新開啟後接著累計。
- 顯示時數排行榜的前 20 名，包括成員與累計時數（以小時與分鐘顯示），不分頁。依累計時數由多到少排列；已離開伺服器的成員顯示「已離開的成員」，仍然列入。統計關閉時仍然顯示既有資料，並註明目前沒有在統計。

**自動禁言**
- 設定項目：是否啟用、警告次數 N、禁言時長。預設不啟用；啟用時的預設值是 3 次、10 分鐘。
- N 的範圍是 1 到 20 次；禁言時長最短 1 分鐘、最長 7 天，與 `/timeout` 的上限一致。
- **計數規則**：只算這個伺服器發出的「警告」紀錄，不論是否存入跨群系統；從這個伺服器最後一次對該成員禁言之後開始算。禁言、踢出、停權紀錄不計入次數。
- **觸發**：新增警告後，該成員的計數大於等於 N 時，bot 立即禁言他設定的時長。例如管理員把 N 調低，或剛啟用時計數已經超過 N，下一次警告就會觸發。後台與 `/warning add` 新增的警告都會觸發。
- **移除紀錄**：計數一律照目前剩下的紀錄計算。移除一筆禁言紀錄，包括 bot 的自動禁言，等於撤銷那次歸零，之前的警告會重新算進來。
- 觸發時寫一筆禁言紀錄：只在這個伺服器，執行者記為 bot，原因是「累計 N 次警告自動禁言」。這筆紀錄讓計數歸零。
- 新增警告的回覆或公告裡註明已自動禁言與禁言時長。
- 對象不在伺服器裡，或 bot 缺少 Moderate Members、位階不夠時，警告照常寫入，但不禁言；回覆裡說明自動禁言失敗的原因，不寫禁言紀錄。
- bot 缺少 Moderate Members 時，設定畫面顯示警告：自動禁言無法執行。

**權限與指令**
- 改基本設定需要 Manage Server。
- 新增指令 `/server setting`，選項是語音時數統計（開／關）、自動禁言（開／關）、警告次數、禁言時長（格式同 `/timeout`），只填要改的項目；不帶任何選項時顯示目前設定。同樣需要 Manage Server。

### 警告

**紀錄清單**
- 列出這個伺服器發出的所有紀錄：警告、禁言、踢出、停權，依時間由新到舊排列，每頁 50 筆。
- 可以依成員與種類篩選。
- 每筆顯示編號、種類、對象、執行者、原因、時間；禁言加上時長，存入跨群系統的加上標示。
- 每筆可以展開成與 `/warning get` 相同的警告單內容。

**查詢成員的跨群紀錄**
- 只能查目前在這個伺服器的成員。這比 `/warning list` 嚴格（指令可以查任何使用者），限制只套用在網頁。
- 顯示內容與 `/warning list` 相同：該成員在所有伺服器存入跨群系統的紀錄，加上這個伺服器只在本伺服器的紀錄。

**新增警告與懲處**
- 可以執行四種動作：警告、禁言、踢出、停權。
- 對象：
  - 警告與停權可以用使用者 ID 執行，對象不必在伺服器裡；停權可以用來封鎖還沒加入的人。這是網頁比指令寬鬆的地方，`/warning add` 與 `/ban` 維持只能對伺服器內的成員。
  - 禁言與踢出只能對目前在伺服器裡的成員。
  - 不能對 bot 執行，也不能對自己執行。
  - 使用者 ID 對不到任何 Discord 使用者時擋下並說明。對已經被停權的人再停權，視為成功，不重複寫紀錄。
- 各動作的選項與指令一致：
  - 警告：原因（必填，100 字以內）、是否存入跨群系統。
  - 禁言：時長（最長 7 天）、原因、是否存入跨群系統、刪除最近訊息的秒數。
  - 踢出：原因、是否存入跨群系統。
  - 停權：原因（必填）、是否存入跨群系統、刪除最近訊息的秒數，選項與指令相同。
- **公告**：四種動作都可以選一個文字頻道公告，也可以不公告。公告內容統一為 @ 對象，加上含紀錄編號的紀錄 embed。觸發自動禁言時，一併寫在警告的公告裡。
- 四種動作成功後一律寫一筆紀錄：沒勾「存入跨群系統」時寫成只在本伺服器，勾選時存入跨群系統。
- 動作本身失敗時，例如 bot 缺權限或位階不夠，告知原因，不寫紀錄。
- 動作成功但公告失敗時，照樣寫紀錄，另外提示公告失敗的原因。刪除最近訊息時有略過的頻道，比照指令列出略過的數量。
- 只看權限，不檢查操作者與對象的身分組位階，與指令一致。

**移除紀錄**
- 只能移除這個伺服器發出的紀錄，與指令一致。移除要二次確認。
- 要移除的紀錄已經被移除時，視為成功，並更新清單。
- 移除紀錄不會解除已經執行的禁言或停權。

### 抽獎

**清單**
- 列出這個伺服器的抽獎。進行中的全部列在第 1 頁最上面，不算在分頁筆數內；已結束的依結束時間由新到舊，每頁 20 筆。
- 預設只列最近 90 天內建立的抽獎，可以切換成顯示全部。進行中的抽獎不受 90 天限制。
- 每筆顯示獎品、發起人、所在頻道、狀態（進行中或已結束）、參加人數、中獎人數，以及結束時間；進行中的顯示預計開獎時間。
- 沒有任何抽獎時，顯示簡短說明：用 `/giveaway create` 發起抽獎。

**單一抽獎**
- 顯示獎品、描述、發起人、所在頻道與跳到抽獎訊息的連結、建立時間、結束時間或預計開獎時間、中獎人數、重抽次數。
- 列出參加者名單（成員與參加時間）與中獎者。已離開伺服器的成員顯示「已離開的成員」。
- 進入頁面時載入，另有手動重新整理，不即時更新。

**提前結束**
- 只有進行中的抽獎可以提前結束，要二次確認。
- 效果與發起人按下「結束抽獎」相同：立即開獎、更新抽獎訊息，並在原頻道公告中獎者。
- 抽獎訊息已被刪除時，照樣開獎，改成在原頻道發一則一般訊息公告。原頻道已不存在或 bot 無法在原頻道發言時，照樣開獎並記下中獎者，告知管理員沒有公告的原因。
- 執行當下抽獎已經結束，例如剛好到期或發起人剛按下結束，視為成功，並顯示最新結果。

**重抽**
- 只有已結束的抽獎可以重抽，要二次確認。
- 選項與 `/giveaway redraw` 相同：整批重抽，不保留原本的中獎者；或指定一位中獎者，取消他的資格並抽出替補。已離開伺服器的中獎者也可以指定。
- 重抽後回覆原抽獎訊息公告新的中獎者，並把抽獎訊息上的結果更新為目前的中獎者，重抽次數加一。
- 抽獎訊息已被刪除、原頻道已不存在或 bot 無法發言時，處理方式與〈提前結束〉相同。
- 沒有足夠的參加者可以抽出替補時，照指令現有的行為處理，並告知管理員。

**權限**
- 看、提前結束、重抽都需要 Manage Messages。後台的這兩個動作不需要是發起人，是比指令與按鈕寬鬆的地方；Discord 內的按鈕與指令維持只有發起人能操作。

### 指令的修改

- **反應身分組**：bot 重啟時，不再自動刪除頻道已不存在的紀錄。`/reactrole add` 新增的按鈕排在最後；`/reactrole editmessage` 修改內容時，一併更新 bot 記住的內容。
- **私人頻道**：`/ticket setup` 支援大廳的全部設定，包括選既有頻道或新建、私人頻道所在分類、管理身分組、前綴、每人一張、同時開啟上限、大廳訊息的文字與按鈕文字。embed 只能在後台編輯。指令以大廳頻道辨識大廳：指定的頻道已經是大廳就修改它，只改有填的選項；不是就新建。指令提供最多 3 個管理身分組選項，有填時取代全部管理身分組，更多的到後台設定；另有「清空上限」「清空管理身分組」選項。開單按鈕的 emoji 也能設定。私人頻道內的鎖定、重開、刪除按鈕照〈鎖定、重開與刪除〉的權限。
- **禁言、踢出、停權**：`/timeout`、`/kick`、`/ban` 不論是否勾選「存入警告系統」，一律寫一筆紀錄，對象是 bot 時照舊不寫。沒勾選時寫成只在本伺服器的紀錄，勾選時存入跨群系統。`/kick`、`/ban` 的回覆改成與網頁公告相同的格式。這樣自動禁言的計數才會在每次禁言後歸零，紀錄清單也看得到所有懲處。
- **警告**：`/warning add` 新增警告後，照〈自動禁言〉的規則判斷是否觸發。
- **基本設定**：新增指令，見〈基本設定〉。
- **抽獎**：`/giveaway redraw` 改成與後台重抽相同：回覆原抽獎訊息公告，並更新抽獎訊息上的結果；下指令的人另外收到只有自己看得到的完成提示。
- 其他指令行為維持現況。網頁上比指令嚴格的限制只套用在網頁。

### 指令與網頁的一致性

- 網頁與指令改的是同一份設定與紀錄：用指令設定的反應身分組、大廳、伺服器設定與警告紀錄，網頁上看得到也改得了；反之亦然。

### 同時編輯、錯誤與權限

- 反應身分組、私人頻道大廳、基本設定的存檔與刪除，衝突比對沿用第一版：存檔或刪除時，如果資料在打開表單後被任何來源改過，就擋下並顯示最新版本，剛輸入的內容保留在表單上。表單暫存也沿用第一版。
- 鎖定、重開、刪除私人頻道，以及移除警告紀錄，執行時以當下狀態為準：目標已經是要求的狀態時視為成功，並更新畫面。
- bot 已不在伺服器、使用者沒有權限、session 過期、Discord 授權失效時，行為與第一版相同。
- 頁面上的限制只是方便操作；權限、身分組可選範圍、訊息與欄位長度、按鈕數量、開單限制、懲處對象等限制，都要在伺服器端再檢查一次，直接呼叫 API 也繞不過。

## 驗收條件

**進入與導覽**
- 只有 Ban Members 的使用者看得到伺服器、進得去，只看到警告區塊；能停權，不能新增警告。
- 只有 Manage Roles 的使用者進入後停在反應身分組，看不到通知與動態語音。
- 有 Manage Channels 的使用者從清單進入，仍然停在通知。
- 直接打開沒有權限的區塊網址，看到沒有權限的提示，並被導到第一個有權限的區塊。

**反應身分組**
- 在網頁選頻道、編排文字與 embed、加三顆按鈕後存檔，Discord 上出現相同內容的訊息；按下按鈕取得身分組，再按一次移除。
- 調整按鈕順序後存檔，Discord 上的按鈕順序跟著改；第 6 顆按鈕排在第二列。
- 貼上 bot 一則只有文字與一般 embed 的既有訊息連結並加上按鈕，訊息下方出現按鈕；編輯器帶入原本的內容，修改後 Discord 上的內容跟著改。
- 貼上別的伺服器的訊息連結，或不是 bot 發的訊息，被擋下並看到原因。
- 從最近訊息挑選時，列出該頻道最近 100 則訊息中 bot 發的，最多 25 則。
- 位階不低於 bot 的身分組，以及不低於操作者的身分組，在選單中停用並說明原因；伺服器擁有者操作時，只有不低於 bot 的身分組會停用。
- 選了帶 Administrator 的身分組，看到危險權限警告，仍然可以存。
- 用 `/reactrole add` 新增的按鈕，網頁上看得到，排在最後。
- 刪除反應身分組訊息時選「只拿掉按鈕」，Discord 訊息還在、按鈕消失；選「刪除訊息」，訊息消失。
- 在 Discord 手動刪除反應身分組訊息後重啟 bot，網頁仍然看得到該紀錄並標示失效；重新發送到另一個頻道後，新訊息有原本的內容與按鈕，按鈕可以運作。
- 刪除按鈕對應的身分組後，網頁上該按鈕標示失效。
- 拔掉 bot 的 Manage Roles 後打開頁面，看到缺少的權限與後果。

**私人頻道**
- 在網頁建立兩個大廳，各自設不同的管理身分組與前綴；從大廳 A 開單得到 `<前綴A>-0001`，只有建立者、A 的管理身分組與 bot 看得到。
- 大廳開啟「每人一張」時，同一人在同一大廳開第二張，被告知已有的頻道；在另一個大廳仍然可以開。
- 上限設為 2，已有兩張未刪除的頻道（含已鎖定）時，第三人開單被告知已額滿；刪除一張後可以開。
- 建立者按下鎖定後，建立者與管理身分組都不能發言；建立者看不到重開按鈕可按，管理身分組按重開後恢復發言。
- 私人頻道在 Discord 被手動刪除後，沒有打開後台，建立者直接再開單，可以成功開出新的頻道。
- 在網頁刪除私人頻道，確認視窗寫明對話無法復原，確認後頻道從 Discord 消失，清單不再顯示。
- 在 Discord 手動刪除私人頻道後重新整理，清單不顯示該頻道，也不再占用名額。
- 移除大廳後，大廳不能再開單，大廳頻道還在；它底下的私人頻道仍在清單，可以鎖定、重開、刪除。
- 用 `/ticket setup` 設定管理身分組、前綴與上限，網頁上看到相同設定。
- 既有測試版的大廳在網頁上顯示預設設定，既有的 `ticket-<名稱>` 頻道出現在清單。
- 刪除大廳頻道後，網頁把大廳標示失效；重新選頻道後大廳訊息重新發出，可以開單。

**基本設定**
- 在網頁開啟語音時數統計後，不必重啟 bot，在語音頻道待幾分鐘，排行榜出現時數；關閉後時數不再增加，排行榜仍然顯示。
- 自動禁言設為 2 次、10 分鐘：在網頁警告某成員兩次，第二次後他被禁言 10 分鐘，公告與回覆寫明已自動禁言，紀錄清單多一筆執行者為 bot 的禁言。之後再警告一次不觸發，再一次才觸發。
- 用 `/warning add` 累計到 N 次，同樣觸發自動禁言。
- 自動禁言觸發時，bot 缺少 Moderate Members：警告照常寫入，回覆說明自動禁言失敗的原因。
- 用 `/timeout` 不勾選存入紀錄禁言某成員後，該成員的自動禁言計數歸零。
- 新的基本設定指令改的設定，網頁上看得到；反之亦然。
- 只有 Manage Channels 的使用者看不到基本設定區塊，直接呼叫 API 改設定被拒絕。

**警告**
- 紀錄清單列出這個伺服器用指令與網頁寫下的四種紀錄，可以依成員與種類篩選。
- 查詢某成員的跨群紀錄，看到他在其他伺服器存入跨群系統的紀錄；查詢不在伺服器裡的使用者，被拒絕。
- 用使用者 ID 停權一個還沒加入的人，之後他無法加入伺服器；用 ID 禁言不在伺服器的人，被拒絕。
- 從網頁停權時選了公告頻道，該頻道出現與指令相同的公告；Discord 稽核紀錄的原因開頭是「<管理員名稱> 透過後台：」。
- bot 位階低於對象時從網頁踢出，看到失敗原因，沒有寫紀錄。
- 移除別的伺服器發出的紀錄被拒絕；移除本伺服器的紀錄後，清單不再顯示，原本的停權不受影響。

**抽獎**
- 有 Manage Messages 的使用者在抽獎區塊看到這個伺服器的抽獎，進行中的排在最上面；預設看不到 90 天前的抽獎，切換成顯示全部後看得到。
- 點進一個抽獎，看到參加者名單與中獎者，與 Discord 上的結果一致。
- 不是發起人的管理員在後台提前結束進行中的抽獎，抽獎訊息更新為結果，原頻道出現中獎公告。
- 在後台指定一位中獎者重抽，他的資格被取消並抽出替補，原頻道出現公告，重抽次數加一。
- 抽獎訊息被刪除後在後台提前結束，照樣開獎，原頻道出現一則一般訊息的中獎公告。
- 拔掉 bot 在原頻道的 Send Messages 後在後台重抽，照樣重抽，並看到沒有公告的原因。
- 在後台重抽後，抽獎訊息上的結果更新為新的中獎者。
- 沒有 Manage Messages 的使用者看不到抽獎區塊，直接呼叫 API 結束或重抽被拒絕。

**其他**
- A、B 同時編輯同一則反應身分組訊息，A 先存；B 存檔時被擋下，看到最新版本，B 輸入的內容仍在表單上。
- 沒有權限時直接呼叫各區塊的 API，請求被拒絕；直接呼叫 API 設定 bot 無法發放的身分組、超過 25 顆按鈕、超過開單上限，請求被拒絕。
- 在 360px 寬的畫面下，以上流程都能完成，不需要橫向捲動。

## 考慮過但捨棄的方向

- **反應身分組只做基本的增刪改**：解決不了訊息只能純文字、按鈕順序不能改的問題。
- **反應身分組的單選、只拿不退、下拉選單模式**：會改變 bot 的按鈕行為，這次不做。
- **embed 只開放標題、說明、顏色**：使用者要接近完整的 embed，用來做規則說明或身分組介紹。
- **反應身分組只能由後台新發訊息**：既有的 bot 訊息也要能掛，與指令一致。
- **失效的反應身分組紀錄自動清掉**：訊息被誤刪時管理員就無法重新發送；選擇標示失效、由管理員處理。
- **按鈕手動指定在第幾列**：增加表單複雜度，自動每 5 顆換列已經夠用。
- **私人頻道只有一個大廳**：使用者需要依用途分開，例如檢舉與合作洽談。
- **私人頻道的開單表單與 transcript**：範圍太大，這次不做；代價是刪除頻道後對話無法復原。
- **私人頻道鎖定後自動刪除**：刪不刪由管理員決定。
- **開單限制只算未鎖定的頻道**：使用者選擇未刪除的都算，避免鎖定後馬上再開一張。
- **後台只能看警告、不能懲處**：使用者要後台成為完整的懲處工具。
- **懲處檢查身分組位階**：選擇與指令一致，只看權限。
- **自動禁言的時長每次加倍**：規則較複雜，這次用固定時長。
- **抽獎區塊只看不改**：發起人不在時，就沒人能結束或重抽。
- **從後台發起抽獎**：這次沒有需求，發起仍用指令。
- **伺服器頁維持只有 Manage Channels 能進**：只負責懲處或身分組的管理人員就無法使用後台。

## 已知限制與風險

- **刪除私人頻道後對話無法復原**：沒有 transcript，已接受；確認視窗會寫明。
- **反應身分組的危險權限只警告不擋**：任何人按下按鈕都可能取得高權限。與指令一致，已接受。
- **懲處不檢查身分組位階**：有 Kick Members 的人可以在後台踢出位階比自己高的成員，只要 bot 位階夠。與指令一致，已接受。
- **預覽只是近似**：Discord 實際顯示可能和預覽略有差異。
- **警告的查看不需權限**：任何能進伺服器頁的人都能看全部懲處紀錄，例如只有 Manage Roles 的人。與指令一致，已接受。
- **`/timeout`、`/kick`、`/ban` 的紀錄行為改變**：沒勾選存入系統的懲處，以前不留紀錄，之後會留一筆只在本伺服器的紀錄，會出現在紀錄清單與 `/warning list`。
- **移除禁言紀錄可能立刻觸發自動禁言**：移除後舊警告重新計入，下一次警告就可能觸發。已接受，換取計數永遠和紀錄一致。
- **權限仍有第一版的 10 分鐘快取空窗**：見第一版規格。

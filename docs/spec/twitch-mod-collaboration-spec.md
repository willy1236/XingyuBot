# XingyuBot 實況主後台：頻道 mod 協作

## 背景與動機

實況主後台第一階段（見 [twitch-streamer-dashboard-spec.md](twitch-streamer-dashboard-spec.md)）只讓頻道的實況主本人進入該頻道的後台，修改紀錄也只有 bot owner 在營運入口看得到。頻道的 mod 雖然能在聊天室用 `!add_cmd`、`!edit_cmd`、`!remove_cmd` 管理自訂指令，卻不能進後台，計時訊息與事件回應只能由實況主一個人設定。

這份規格開放頻道的 mod 進入實況主後台協作，讓實況主把日常設定分給 mod，同時讓實況主與 mod 看得到誰改了什麼。

## 目標與非目標

**目標**
- 實況主能把自訂指令、計時訊息、事件回應的設定工作分給頻道的 mod。
- 實況主與 mod 都看得到每一次修改是誰、什麼時間、從哪裡、改了什麼。

**非目標**
- 頻道 mod 以外的協作者，例如 Twitch 的頻道編輯者（Editor）或實況主自行指定的人。
- 逐位 mod 分別設定權限：所有 mod 的權限相同。
- mod 修改設定時主動通知實況主：實況主看修改紀錄即可。
- 聊天室管理、觀眾點數、實況資訊與事件紀錄等其他後續階段的功能。

## 已定案的前提

- 本規格調整 twitch-streamer-dashboard 規格的兩條決定：
  - 「第一階段只有頻道的實況主本人能進該頻道的後台」改為頻道的 mod 也能進入，範圍見〈mod 能做什麼〉。
  - 「修改紀錄第一階段只有 bot owner 在營運入口能看」改為實況主與 mod 在頻道後台也看得到。
- 後續階段的順序調整：mod 協作提前到聊天室管理、觀眾點數與點數用途、實況資訊與事件紀錄之前。
- 「誰是 mod」一律以 Twitch 上該頻道的 mod 名單為準，系統不另外維護名單。名單用實況主啟用 bot 時已授權的權限讀取，既有頻道不必重新授權。

## 範圍

- 頻道 mod 能用 Twitch 或析域登入，進入自己擔任 mod 的頻道後台。
- 頻道清單與登入後落地頁配合 mod 調整。
- mod 能修改自訂指令、計時訊息、事件回應，其餘區塊只能看狀態。
- 頻道後台新增修改紀錄區塊，實況主與 mod 都看得到。
- 實況主能開關 mod 協作，關閉時同時關掉 mod 在聊天室管理指令的能力。
- 拿掉 mod、關閉協作、授權失效、Twitch 暫時無法回應時的存取規則。

## 詳細規格

### 用詞

- **自己的頻道**：登入的 Twitch 帳號本身的頻道，不論狀態，與第一階段相同。析域登入時是每個連結的 Twitch 帳號各自的頻道。
- **mod 頻道**：登入者擔任 mod、而且符合〈登入與頻道清單〉列出條件的頻道。同一個頻道同時是自己的頻道時，只算自己的頻道。
- **操作**：對後台的任何請求，包含載入頁面、讀取資料與儲存。

### 誰是協作者

- 協作者是 Twitch 上該頻道的 mod。
- bot 自己的帳號也是各頻道的 mod，但不算協作者：bot 帳號登入時沒有任何 mod 頻道，它自己的頻道照第一階段規則處理。
- mod 不必是域民。
- 除了本規格新增的修改紀錄與 mod 協作開關，實況主本人的權限照第一階段不變。

### 登入與頻道清單

| 登入方式 | 看得到的 mod 頻道 |
|---|---|
| Twitch | 這個 Twitch 帳號擔任 mod 的頻道 |
| 析域帳號 | 這個析域帳號連結的每個 Twitch 帳號擔任 mod 的頻道 |
| Discord | 無 |

- 擔任 mod 的頻道要同時符合下列條件，才算 mod 頻道、出現在清單：
  - 狀態是已啟用、部分暫停、已停用或已停權。未啟用的頻道不列。
  - 實況主沒有關閉 mod 協作。
  - 系統能確認這個人目前是該頻道的 mod，規則見〈存取的確認〉。
- 已停權的 mod 頻道照第一階段規則，打開時顯示「此頻道已被停權」與聯絡方式。
- 頻道清單的排序與標示：自己的頻道在前，標示「我的頻道」；mod 頻道在後，標示「mod」。同一類之內依頻道名稱排序。
- 登入後的落地頁維持現行：三種登入方式都進「我的」。「我的」列出的頻道一併包含 mod 頻道，排序與標示同上。

### mod 能做什麼

| 區塊 | 實況主 | mod |
|---|---|---|
| 自訂指令 | 可修改 | 可修改 |
| 計時訊息 | 可修改 | 可修改 |
| 事件回應 | 可修改 | 可修改 |
| 修改紀錄 | 可查看 | 可查看 |
| AutoMod 最近擋下的訊息 | 可查看 | 可查看 |
| 轉發 Discord | 可修改（需析域登入） | 只看狀態 |
| 啟用、停用 | 可操作 | 只看狀態 |
| 權限問題與一鍵修復 | 可操作 | 只看狀態 |
| mod 協作開關 | 可操作 | 只看狀態 |
| 刪除所有資料 | 可操作 | 不能操作 |

- 「只看狀態」指 mod 看得到目前的設定與狀態，例如部分暫停的原因與受影響的功能，但沒有修改或操作的按鈕。
- 轉發 Discord：mod 不論用哪種方式登入，都看得到目前轉發到哪個 Discord 伺服器與頻道。第一階段「只用 Twitch 登入時顯示需要析域帳號」的規則只適用於實況主本人。
- mod 對所有不能修改或操作的區塊，即使直接呼叫也一律被拒絕，不只是畫面上沒有按鈕。
- mod 的修改套用第一階段對實況主的所有規則，包含 AutoMod 檢查、同時編輯的衝突處理、即時生效。

### 修改紀錄

- 頻道後台新增修改紀錄區塊，實況主與 mod 都看得到。
- 顯示的是該頻道保留下來的整份紀錄，與營運入口看到的相同：包含本規格上線前的紀錄、「刪除所有資料」之前的紀錄、來源是聊天室的修改，以及轉發 Discord 設定的修改。第一階段規格只要求記錄指令、計時訊息、事件回應，轉發設定的修改是實作時一併記錄的，見 [twitch-streamer-dashboard 任務卡](../tickets/twitch-streamer-dashboard.md) 的 W-04、W-11。
- 每筆紀錄顯示操作者、時間、來源（後台或聊天室）、修改前與修改後。
- 操作者顯示做出修改的 Twitch 帳號名稱，實況主與 mod 都一樣：
  - 用 Twitch 登入時，記登入的 Twitch 帳號。
  - 實況主用析域登入時，記該頻道本身的 Twitch 帳號，不再記 Discord 帳號。
  - mod 用析域登入時，記擔任該頻道 mod 的那個連結 Twitch 帳號；有多個連結帳號都是該頻道 mod 時，記其中第一個。
  - 本規格上線前已寫入的紀錄不改，仍顯示當時的操作者。
- mod 協作開關的開關動作也寫進修改紀錄，操作者是實況主。
- 營運入口看的是同一份紀錄，所以也看得到開關紀錄；除此之外營運入口照第一階段不變。

### mod 協作開關

- 實況主在頻道後台可以開關 mod 協作，預設開啟。上線時既有頻道一律視為開啟。
- 關閉時：
  - mod 不能進入該頻道後台，頻道從 mod 的頻道清單消失，最遲 60 秒內生效。生效後 mod 的下一次操作被擋下，回到頻道清單並看到提示。
  - mod 不能在聊天室用 `!add_cmd`、`!edit_cmd`、`!remove_cmd` 新增、修改、移除指令，最遲 60 秒內生效；mod 下這些指令時，bot 回覆權限不足。實況主本人照常能用。
  - `!list_cmd` 照第一階段規則，不受開關影響。
- 重新開啟後，上述能力恢復。
- 營運入口不顯示各頻道的開關狀態。

### 存取的確認

- 系統用實況主的授權向 Twitch 確認 mod 名單，與頻道狀態無關：已停用、已停權或刪除過資料的頻道，只要實況主的授權仍有效，照樣能確認。
- 實況主在 Twitch 拿掉某人的 mod 後，最遲 60 秒內生效：頻道從他的清單消失，他之後的下一次操作被擋下，回到頻道清單並看到提示。
- Twitch 新增的 mod，最遲 60 秒內出現在他的頻道清單。
- 實況主的授權失效，例如撤銷授權或 token 過期且無法續期時，系統無法確認誰是 mod：所有 mod 都不能進入該頻道後台，頻道也不出現在 mod 的清單。實況主本人照常能進入並修復，修復後最遲 60 秒內 mod 恢復存取。
- Twitch 暫時無法回應，例如逾時或伺服器錯誤時：沿用最後一次確認的結果。最後一次確認時是 mod 的人照常能用，不是 mod 的人照常被擋下；從沒確認過的人一律擋下。沿用沒有期限，直到 Twitch 恢復回應。
- 「回到頻道清單並看到提示」的提示文字交給設計決定。

## 驗收條件

**登入與頻道清單**
- A 不是任何頻道的 mod：用 Twitch 登入後進「我的」，只看到自己的頻道，與現行相同。
- A 是 B 頻道的 mod：用 Twitch 登入後，「我的」與頻道清單都看得到 B，自己的頻道排第一並標示「我的頻道」，B 的頻道標示「mod」；自己的頻道還沒啟用時也一樣。
- A 的析域帳號連結了兩個 Twitch，分別是 B、C 頻道的 mod：用析域登入後，個人區同時看得到 B 和 C 的頻道，標示「mod」。
- A 用 Discord 登入：看不到 mod 頻道。
- A 是 B 頻道的 mod，但 B 頻道未啟用：A 的頻道清單沒有 B 的頻道。
- B 頻道已停權，B 的實況主授權仍有效：A 的清單有 B 的頻道，打開時看到「此頻道已被停權」與聯絡方式。
- bot 帳號登入時，沒有任何 mod 頻道。

**mod 能做什麼**
- mod 在後台新增自訂指令，立即能在聊天室觸發；新增計時訊息、修改事件回應文字也立即生效。
- mod 新增會被 AutoMod 擋下的指令，無法儲存。
- mod 打開轉發 Discord、啟用與停用、權限問題、mod 協作開關時，看得到目前的狀態，但沒有修改或操作的按鈕。
- mod 的頁面上沒有「刪除所有資料」的按鈕。
- mod 直接呼叫轉發 Discord 修改、啟用、停用、修復、協作開關、刪除所有資料，一律被拒絕。
- 頻道因為 bot 被拿掉 mod 而部分暫停時，mod 看得到暫停的原因與受影響的功能。

**修改紀錄**
- mod 修改指令後，實況主在頻道後台的修改紀錄看到這次修改的操作者是該 mod 的 Twitch 帳號名稱，以及時間、來源與修改前後。
- 實況主用析域登入修改指令，修改紀錄的操作者是頻道的 Twitch 帳號名稱，不是 Discord 名稱。
- 實況主修改計時訊息後，mod 也看得到這筆紀錄。
- 有人在聊天室用 `!add_cmd` 新增指令，修改紀錄的來源顯示為聊天室。
- 實況主關閉 mod 協作後，修改紀錄多一筆操作者是實況主的開關紀錄。
- 本規格上線前已有的紀錄，在頻道後台也看得到。

**mod 協作開關**
- 實況主關閉 mod 協作後：最遲 60 秒內 mod 的頻道清單不再出現這個頻道；mod 在聊天室用 `!add_cmd` 無法新增指令，bot 回覆權限不足；實況主本人在聊天室照常能用。
- mod 正在編輯時實況主關閉協作：生效後 mod 下一次儲存被擋下，回到頻道清單並看到提示。
- 重新開啟後，mod 又能進入後台、也能在聊天室管理指令。

**存取的確認**
- 實況主在 Twitch 拿掉 A 的 mod：最遲 60 秒內 A 的頻道清單沒有這個頻道，A 不能再修改。
- 實況主在 Twitch 新增 A 為 mod：最遲 60 秒內 A 的頻道清單出現這個頻道。
- 實況主撤銷授權：所有 mod 都不能進入該頻道後台；實況主修復授權後，最遲 60 秒內 mod 恢復存取。
- Twitch 暫時無法回應：原本確認是 mod 的人照常能用；從沒確認過的人被擋下。

## 考慮過但捨棄的方向

- **實況主逐一指定協作者，可以不限 Twitch mod**：要另外維護一份名單，與 Twitch 上的 mod 不同步；這次只需要讓既有的 mod 分擔工作。
- **mod 協作延伸到可調整聊天室管理指令的範圍**：超出這次要解決的問題。
- **Twitch 的頻道編輯者（Editor）也算協作者**：要多一個 Twitch 權限，既有頻道得重新授權。
- **mod 也能修改轉發 Discord**：轉發牽涉 Discord 伺服器的權限與析域登入，維持只有實況主能改。
- **mod 看不到沒有權限的區塊**：mod 看得到部分暫停等狀態，才能提醒實況主修復。
- **修改紀錄只給實況主看**：多人協作時 mod 之間也需要知道誰改了什麼。
- **實況主授權失效時沿用最後一次確認的 mod 名單**：被拿掉 mod 的人可能繼續進得來，確認不了就不放行。
- **mod 修改後在後台顯示未讀提示給實況主**：看修改紀錄就夠。

## 已知限制與風險

- **實況主授權失效時 mod 也被擋下**：實況主沒修復前，mod 不能幫忙。這是「確認不了就不放行」的代價。
- **拿掉 mod 或關閉協作後最多 60 秒的空窗**：這段期間內的修改仍會成功，與伺服器管理後台的權限變更規則一致。
- **Twitch 暫時無法回應時沿用最後結果**：這段期間內被拿掉 mod 的人仍能修改，直到 Twitch 恢復且確認後才被擋下。接受這個風險，換取短暫異常不影響 mod 的使用。
- **mod 的權限一致**：實況主不能只開放部分區塊給某位 mod。
